# data postcard

редактор небольших графиков для постов, отчётов и личных итогов. внесите цифры в таблицу, добавьте заголовок и пояснение, выберите оформление — и скачайте готовую открытку.

**[открыть редактор →](https://chebaturkin.github.io/data-postcard/)**

![редактор data postcard: готовая открытка слева, редактируемая таблица справа](docs/images/editor.png)

## для чего он пригодится

когда нужно показать несколько чисел вместе с контекстом: куда ушли деньги за месяц, сколько материалов вышло на каждой площадке, как менялась температура или сколько времени нашлось для чтения. открытку можно добавить в пост, отправить в переписке или вставить в отчёт.

внутри есть пять примеров. они помогают попробовать инструмент и понять, как будут выглядеть ваши данные. цифры в примерах демонстрационные.

## собрать свою открытку

1. в строке источника выберите пример и замените цифры и названия в таблице. строки можно добавлять и удалять. нажмите «обновить открытку».
2. во вкладке «текст» добавьте заголовок, короткое пояснение и единицы измерения.
3. во вкладке «график» выберите представление и колонки. палитра и формат находятся рядом с результатом. итог можно показать как сумму или среднее, либо скрыть.
4. скачайте png для публикации, svg для вёрстки или html, который открывается отдельной страницей. перед скачиванием изменения таблицы применяются автоматически. если есть ошибка, редактор выделит ячейку и предложит её исправить.

если данные уже собраны, раскройте «загрузить файл или вставить таблицу». можно перетащить csv или json, вставить текст или скопировать ячейки из excel и google sheets. первая строка должна содержать названия колонок. csv может использовать запятые или точку с запятой, а ячейки из таблицы — табуляцию.

```csv
категория,сумма
продукты,18400
кафе,6200
транспорт,3800
```

полосы и точки помогают сравнить значения. линия показывает изменения по датам, календарь — записи по дням. для линии и календаря нужна колонка с датами, например `2026-10-14`.

## данные и черновик

данные обрабатываются в браузере и не отправляются на сервер. аккаунт не нужен. черновик с применёнными данными, текстом и настройками сохраняется в этом браузере и восстанавливается после перезагрузки. неприменённые ячейки, включая ошибки, тоже сохраняются отдельно: они появятся в таблице, а открытка сохранит последний корректный результат. текст и настройки сохраняются сразу.

кнопка «вернуть пример чтения» возвращает пример чтения. замену источника и возврат примера можно отменить кнопкой сверху. черновик привязан к браузеру и адресу сайта; очистка данных сайта удалит его. если браузер запрещает сохранение, редактор продолжит работать и сообщит об этом.

чтобы вернуться к открытке позже или перенести её в другой браузер, нажмите «сохранить черновик» в верхней строке — скачается файл `*.postcard.json` с данными, неприменёнными ячейками, текстом и настройками. «открыть файл» восстановит его для редактирования. можно хранить несколько таких файлов; автоматический черновик в браузере остаётся один.

файл черновика отличается от обычной таблицы. общая загрузка распознаёт csv, json с данными и сохранённый черновик; открыть черновик отдельно можно во вкладке «данные». лимит файла открытки тоже **1 мб**. повреждённый или неподдерживаемый файл сохраняет текущую работу. сохранение и открытие файла работают и при недоступном хранилище браузера. перед пересылкой файла проверьте данные внутри него.

если длинный текст оставляет слишком мало места графику, редактор предложит сократить его или выбрать сторис и заблокирует экспорт до исправления. плотные данные можно проверить в масштабе 100%.

инструмент рассчитан на **2–20 строк** и файлы csv/json до **1 мб**. пустые значения можно оставить видимыми. если в таблице или файле есть ошибка, предыдущая открытка сохраняется. большие таблицы лучше предварительно сократить до нужных категорий или периода.

два размера: **1200 × 900** для поста и **1080 × 1920** для сторис. кнопка «посмотреть открытку» открывает результат с масштабом 100% и экспортом. на телефоне и планшете редактор идёт первым, а компактная миниатюра остаётся рядом с вкладками. png, svg и автономный html используют ту же сцену и встроенные локальные шрифты. несовместимые настройки сохраняют предыдущий результат и блокируют экспорт до исправления. html также содержит раскрываемую таблицу применённых данных, поэтому перед пересылкой стоит проверить содержимое таблицы.

## запустить локально

приложение — статический сайт на html, css и javascript. сборка и установка зависимостей для запуска не нужны. подойдёт любой статический сервер, например:

```bash
python3 -m http.server 8000
```

откройте [локальный редактор](http://localhost:8000).

## проверить изменения

для тестов парсера, таблицы, черновика, сортировки, графиков и экспорта нужен node.js:

```bash
npm test
```

для браузерной проверки:

```bash
npm install
npx playwright install chromium
npm run test:browser
```

браузерный тест сам запускает статический сервер. он проверяет редактирование, импорт, ошибки в ячейках, актуальность скачиваемых данных, вкладки с клавиатуры, черновик и переносимые файлы открыток, недоступное хранилище, отмену устаревшего чтения, палитры, виды графиков, размеры скачанных png и отсутствие переполнения на экранах от 320 до 1440 пикселей.

обновить скриншоты в readme:

```bash
npm run screenshots
```

## проверка компоновки

`node tests/scene-layout-browser.mjs` проверяет геометрию длинных текстов, двадцати категорий, редких событий и совпадающих или тесно расположенных дат. `npm run test:browser` проверяет ширины 390, 768 и 1440 px, работу просмотра, восстановление правок, отмену источника, клавиатуру и экспорт.
