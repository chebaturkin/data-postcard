# data postcard: правила проекта

редактор небольших графиков для постов, отчётов и личных итогов. вход: редактируемая таблица на 2–20 строк, csv/json-файл до 1 мб или вставка ячеек. данные остаются в браузере. черновик хранит применённые данные и настройки локально.

сохраните четыре представления: полосы, точки, календарь и линия по датам; пять палитр; размеры 1200 × 900 и 1080 × 1920; экспорт в png, svg и автономный html. сумма, среднее и отсутствие итога — отдельный выбор пользователя. ошибки ввода не заменяют готовую открытку.

оформление: тёплые цвета, скругления у самой открытки и полей ввода, крупный предпросмотр и компактные настройки. без курсивных акцентов в заголовке, декоративных подсказок, ряда мини-карточек и отдельных рекламных блоков. примеры выбираются в списке у таблицы; скачивание находится прямо под открыткой. убирайте повторяющиеся подписи, декоративные индексы и надзаголовки. без градиентов, стекла и лишних призывов. используйте шрифты с хорошей кириллицей и локальными fallback.

авторские тексты проверяйте по chebaturkin-style и chebaturkin-copy. начала предложений и названия продуктов и технологий пишутся строчными. код, пути и технические идентификаторы сохраняют необходимый регистр.

приложение остаётся статическим сайтом для github pages: без обязательного backend, авторизации, api-ключей и внешних моделей. зависимости для разработки не должны требоваться посетителю.

проверяйте desktop/mobile, клавиатуру, focus, reduced motion, пропуски, неверные числа и даты, восстановление черновика и офлайн-экспорт. readme объясняет назначение, ограничения и содержит актуальные скриншоты.
