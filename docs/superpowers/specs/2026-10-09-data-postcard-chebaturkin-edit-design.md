# Data Postcard — редактура и доводка в стиле Тимофея

## Цель

Сделать Data Postcard цельным локальным инструментом: понятные тексты, единый регистр, спокойная редакторская интонация, надёжный импорт и экспорт, читаемый интерфейс на большом и маленьком экране. Сохранить рабочую архитектуру на ванильных HTML, CSS и JavaScript.

## Что сохраняем

- данные обрабатываются только в браузере;
- поддерживаются CSV и JSON на 5–20 строк;
- остаются четыре представления: полосы, точки, календарная сетка и временной маршрут;
- остаются пять тем, Stories 1080 × 1920 и формат 1200 × 900;
- PNG, SVG и автономный HTML строятся из одной SVG-сцены;
- сервер, аккаунт, API, AI и внешняя загрузка данных не появляются.

## Редакторские решения

- пользовательский текст начинается со строчной буквы, если это не имя, бренд или техническое обозначение;
- `Data Postcard`, `CSV`, `JSON`, `PNG`, `SVG`, `HTML`, `Stories` и названия файлов сохраняют необходимый регистр;
- вместо общих обещаний — действие и результат: «перетащите файл», «вставьте строки», «выберите колонку»;
- ошибки называют причину и следующий шаг: ограничения строк, пустую колонку, неверное число или дату;
- «сохранить» уточняется форматом и фактическим действием скачивания;
- английские служебные метки вроде `LOCAL / DATA / 01` и `LANDSCAPE` переводятся или убираются, если они не помогают пользоваться инструментом;
- README описывает реальный сценарий и ограничение «данные не покидают браузер», без рекламных формул.

## Интерфейс и визуальная система

- сохраняется композиция «большая открытка слева, компактные настройки справа»;
- убирается принудительный `text-transform: uppercase` у пользовательских подписей, кнопок и футера;
- шрифтовые токены интерфейса и SVG получают одну последовательную пару display serif + humanist sans/mono с локальными fallback;
- темы используют сплошные заливки, линии и точки; градиенты, стекло, pill-кнопки и dashboard-паттерны не добавляются;
- сохраняются фокус-кольца, touch-target не меньше 44 px, reduced motion и печатный чёрно-белый режим;
- skip-link ведёт на реально фокусируемую область предпросмотра;
- длинные заголовки, пустые значения и Stories проверяются на мобильной ширине.

## Надёжность и защита

- импорт проверяет расширение/тип и размер файла до чтения, чтобы большой или неподходящий файл не перегружал вкладку;
- невалидный импорт не заменяет последнюю рабочую открытку;
- пользовательские значения остаются экранированными в SVG, HTML-метаданных и DOM;
- имена файлов для скачивания очищаются от путей, управляющих символов и пустых значений;
- статусы импорта и экспорта остаются в `aria-live`, а ошибки содержат понятный способ исправления;
- добавляются тесты для лимита файла, копирайта статусов и регрессий в доступности там, где это можно проверить без браузера.

## GitHub Pages

В репозитории появятся:

- `.github/workflows/pages.yml` для публикации статического проекта;
- `404.html` с тем же регистром и коротким объяснением;
- обновлённый README с запуском локально и через GitHub Pages.

Если в проекте по-прежнему нет remote, локальная конфигурация будет готова к публикации. Создание и push публичного репозитория `chebaturkin/data-postcard` выполняются только после проверки итоговых файлов и доступности имени.

## Проверка результата

1. `npm test` проходит полностью.
2. Браузерный smoke pass проверяет стартовый пример, три набора, четыре режима, пять тем, Stories, ошибочный импорт с сохранением открытки и три экспорта.
3. Интерфейс просматривается на desktop и mobile, с клавиатуры, при reduced motion и в print preview.
4. README, метаданные страницы, доступные названия, подсказки и сообщения ошибок используют тот же голос.
5. GitHub Pages workflow и `404.html` проверяются как статические файлы до публикации.

## Границы

Редактура не меняет бизнес-условия, формат данных, состав режимов или внешний сервер. Публикация на GitHub остаётся отдельным внешним действием: сначала готовятся и проверяются файлы, затем при наличии remote выполняется публикация.
