# data postcard: сохранение и исправление данных

## что есть в проекте

небольшой локальный редактор графиков для постов, отчётов и личных итогов. по readme, примерам и коду основной сценарий — заменить цифры в таблице, добавить текст, выбрать оформление и скачать открытку. аудитория — люди, которым нужно понятно показать несколько чисел без настройки большой системы визуализации.

статический html/css/javascript, без зависимостей в браузере и без сервера данных. `data.js` разбирает и проверяет csv/json, `editor.js` проверяет таблицу и восстанавливает черновик, `scene.js` строит общий svg для предпросмотра и экспорта. четыре графика, пять палитр, два размера, 2–20 строк, файлы до 1 мб. единственная зависимость разработки — playwright. сборки и линтера в package.json нет.

история 8–14 октября: импорт и сохранность предыдущего результата, авторские тексты, публикация на github pages, редактируемая таблица, локальный черновик, упрощение интерфейса. актуальные документы от 14 октября уточняют более ранние ограничения и оформление. отдельного AGENTS.md в репозитории и родительских каталогах нет; применены инструкции пользователя и AGENT_PROMPT.md.

при начале исследования в рабочем дереве были незакоммиченные изменения логотипа, интерфейса и скриншотов. во время чтения они вошли в `6ecf0be`; исследование продолжено на этом состоянии, без отката и перезаписи этих изменений.

исходные проверки: 41 модульный тест прошёл. браузерный запуск сначала остановился из-за отсутствующего playwright; после `npm ci` прошли 57 проверок. установка не изменила package.json или lock-файл. подтверждённые пробелы: экспорт читает `state.svg`, хотя изменения таблицы могут ещё находиться только в полях ввода; ошибки таблицы показываются общим сообщением, без маркировки ячейки; экспортируемый html содержит данные, но редактор не умеет возвращать их вместе с оформлением. черновик хранится только по одному ключу в одном браузере.

## поведение и границы

- при любом скачивании изменённая таблица проходит тот же путь, что кнопка «обновить открытку». корректный ввод попадает в результат. некорректный ввод останавливает скачивание, открывает данные и переводит фокус к первой ошибке; предыдущая открытка и сохранённый черновик остаются доступны.
- проверка после применения выделяет все ошибочные поля, связывает их с текстовым описанием и называет строку без учёта заголовка. редактирование снимает отметку с изменённого поля; повторная проверка уточняет остальные ошибки. пустые значения остаются предупреждениями, а не неверными ячейками.
- раздел «сохранить и открыть открытку» содержит две обычные кнопки и короткое объяснение. файл `*.postcard.json` содержит тип `data-postcard`, версию 1, исходные данные и настройки. лимит — 1 мб. старый ключ и формат черновика сохраняются.
- открытие через отдельный input не меняет импорт обычных csv/json. данные файла полностью проверяются до замены состояния. неизвестный тип, версия, повреждённые данные и файл сверх лимита дают понятную ошибку. загрузка имеет видимый статус; последующий ввод или выбор примера отменяет устаревший результат чтения.
- данные не покидают браузер, файлы не содержат выполняемый код. визуальный язык, графики, размеры и палитры сохраняются. без новых зависимостей, аккаунтов и публикации.

## проверка
